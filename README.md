# School Schedule Backend

Backend проект для системы расписания школьных уроков на NestJS.

## Технологии

- **NestJS** - фреймворк для Node.js
- **TypeORM** - ORM для работы с базой данных
- **PostgreSQL** - реляционная база данных

## Установка

1. Установите зависимости:
```bash
npm install
```

2. Создайте файл `.env` на основе `.env.example`:
```bash
cp .env.example .env
```

3. Настройте переменные окружения в файле `.env`:
   - `DB_HOST` - хост PostgreSQL (по умолчанию: localhost)
   - `DB_PORT` - порт PostgreSQL (по умолчанию: 5432)
   - `DB_USERNAME` - имя пользователя БД
   - `DB_PASSWORD` - пароль БД
   - `DB_NAME` - название базы данных
   - `DB_SYNCHRONIZE` - автоматическая синхронизация схемы (true/false)
   - `DB_LOGGING` - логирование SQL запросов (true/false)

4. Убедитесь, что PostgreSQL запущен и база данных создана.

⚠️ **Важно:** Если в базе данных уже есть данные (особенно группы), и вы обновили структуру таблиц (например, добавили обязательные поля), вам нужно **очистить базу данных** перед запуском приложения. TypeORM автоматически пересоздаст таблицы с новой структурой при включенной синхронизации (`DB_SYNCHRONIZE=true`).

### Очистка базы данных

#### Способ 1: Использование скрипта (рекомендуется)

Самый простой способ - использовать встроенный скрипт:

```bash
npm run db:reset
```

Этот скрипт:
- Удалит все таблицы из базы данных
- При следующем запуске (`npm run start:dev`) TypeORM автоматически создаст все таблицы с актуальной структурой
- Seed данные (админ пользователь) будут созданы автоматически

#### Способ 2: Ручная очистка через SQL

Если нужно очистить вручную:

```sql
-- Подключитесь к базе данных PostgreSQL
psql -U postgres -d school_schedule

-- Удалите все таблицы
DROP SCHEMA public CASCADE;
CREATE SCHEMA public;
GRANT ALL ON SCHEMA public TO postgres;
GRANT ALL ON SCHEMA public TO public;
```

#### Способ 3: Пересоздание базы данных

```bash
# Удалить базу данных
dropdb -U postgres school_schedule

# Создать базу данных заново
createdb -U postgres school_schedule
```

После очистки при запуске приложения TypeORM автоматически создаст все таблицы с актуальной структурой.

## Swagger документация

Swagger документация **автоматически генерируется** на основе декораторов в коде. Никаких ручных правок не требуется!

### Доступ к документации

После запуска приложения Swagger UI будет доступен по адресу:
- **Swagger UI:** http://localhost:3000/api

### Автоматическая генерация

Документация генерируется автоматически на основе:
- **`@ApiProperty()`** в DTO и Entity - описывает поля запросов/ответов
- **`@ApiOperation()`** в контроллерах - описывает операции (summary, description)
- **`@ApiResponse()`** в контроллерах - описывает возможные ответы
- **`@ApiTags()`** в контроллерах - группирует endpoints по категориям
- **`@ApiBearerAuth()`** в контроллерах - указывает на необходимость JWT авторизации
- **`@ApiBody()`** в контроллерах - описывает тело запроса

### Генерация Swagger JSON файла

Для экспорта документации в JSON файл (например, для импорта в Postman или другие инструменты):

```bash
npm run swagger:generate
```

Это создаст файл `swagger.json` в корне проекта с полной документацией API.

### Использование Swagger UI

1. Запустите приложение: `npm run start:dev`
2. Откройте http://localhost:3000/api в браузере
3. Для авторизации:
   - Нажмите кнопку **"Authorize"** в правом верхнем углу
   - Введите JWT токен (полученный через `POST /auth/login`)
   - Токен будет автоматически сохраняться между запросами
4. Тестируйте API прямо из Swagger UI:
   - Выберите endpoint
   - Нажмите "Try it out"
   - Заполните параметры
   - Нажмите "Execute"
   - Просмотрите ответ

## Аутентификация и авторизация

### Начальный админ
При первом запуске приложения автоматически создается пользователь-администратор:
- **Логин:** `admin`
- **Пароль:** `admin`

⚠️ **Важно:** Измените пароль после первого входа!

### Роли пользователей
- **admin** - администратор (полный доступ)
- **teacher** - учитель
- **student** - ученик

### API Endpoints

#### Публичные endpoints:
- `POST /auth/login` - авторизация (получение JWT токена)

#### Защищенные endpoints (требуют JWT токен):
- `POST /auth/register` - создание нового пользователя (только для admin)
- `GET /users` - список всех пользователей (только для admin)
- `POST /users` - создание пользователя (только для admin)
- `GET /users/:id` - получение пользователя (только для admin)
- `PATCH /users/:id` - обновление пользователя (только для admin)
- `DELETE /users/:id` - удаление пользователя (только для admin)

Все остальные endpoints (teachers, subjects, groups, classrooms) требуют авторизации.

### Использование JWT токена

После авторизации вы получите токен в ответе:
```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user": { ... }
}
```

Используйте этот токен в заголовке запросов:
```
Authorization: Bearer <your-token>
```

### Guards

- **JwtAuthGuard** - проверяет валидность JWT токена
- **RolesGuard** - проверяет роль пользователя (используется с декоратором `@Roles()`)

### Пример использования guards:

```typescript
@UseGuards(JwtAuthGuard, RolesGuard)
@Roles(UserRole.ADMIN)
@Get('admin-only')
adminOnly() {
  // Доступно только для админа
}
```
